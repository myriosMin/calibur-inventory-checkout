# QR Labels

## TL;DR

- **~500 labels, one per storage compartment — not one per product.**
- **The resistor book gets ~8 page labels, not 157 pocket labels.** Scan the
  page, tap the value. 0402 pockets can't carry a scannable code.
- The QR encodes `https://t.me/<bot>/<app>?startapp=<code>`. The `startapp`
  payload is capped at **64 chars, base64url alphabet only** — so short opaque
  codes, never UUIDs or URLs.
- **Keep the bot and app names short.** They sit in every QR and directly
  determine how small a label can be and still scan.
- **Always print human-readable text under the QR.** This is what keeps the
  store usable when a label is scuffed.
- **Laser on polyester/vinyl, minimum 20 mm QR.** These bins meet flux and IPA;
  paper labels die within a year.
- Budget **~1 day**: ~6–8 hours to stick 500 labels, two people, one afternoon.

---

## The deep link

```
https://t.me/<bot>/<app>?startapp=<code>
```

This opens the Mini App directly, inside Telegram, with `<code>` readable from
`initDataUnsafe.start_param`. It is the *only* entry point — see
[flows.md](flows.md).

### Hard constraints

| Constraint | Value |
|---|---|
| `startapp` payload length | **64 characters max** |
| `startapp` alphabet | `A–Z a–z 0–9 _ -` (base64url) |
| Practical QR target | Version 3 or lower at error correction L |

Verify the exact current limits against Telegram's Bot API docs before the
print run — they're stable, but a print run of 500 labels is an expensive thing
to get wrong.

### Length budget

Every character in the bot name, app name, and code makes the QR denser and the
minimum label bigger. Choose short names **before printing anything**:

```
https://t.me/nusrm_store/s?startapp=A3F9K2      →  46 chars   ✅
https://t.me/nus_robomaster_inventory_bot/store?startapp=...  →  80+  ❌
```

Recommendation: bot `nusrm_store` (or shorter), app `s`. Roughly 45–50
characters total keeps you at QR version 3, which scans reliably at 20 mm.

## Code scheme

Codes live in `scan_codes.code` ([data-model.md](data-model.md)) and are:

- **Opaque** — no product id, no name, no structure to guess or enumerate
- **Short** — 6–8 base64url characters (~10¹⁴ combinations at 8; collision is
  not a concern at 500 labels)
- **Case-sensitive but visually unambiguous** — exclude `0/O` and `1/l/I` from
  the generation alphabet so a human can read a code aloud or type it if a QR
  is damaged
- **Never reused.** A retired code is deactivated, not deleted, so a stale
  sticker found in a drawer gives a clean "this label is retired" rather than a
  wrong hit on some unrelated part.

Codes are generated by the admin dashboard when a label is created, not derived
from the product — which is what lets a damaged label be reprinted with a fresh
code without touching the product record.

## What gets a label

**One label per storage compartment, not per product.** Approximate counts from
the electrical sheet:

| Location | Compartments | `scan_codes.kind` |
|---|---|---|
| Resistor book (rows 355–512) | ~8 pages, ~157 values | `group` |
| Small box — SMD (rows 259–355) | ~95 | `product` |
| Small box — supercap BOM | ~60 | `product` |
| Connectors, Table Shelf (rows 3–48) | ~46 | `product` |
| Through-hole (rows 50–122) | ~73 | `product` |
| Wires, blue rack / rotating shelf (rows 213–256) | ~44 | `product` |
| Tier A shelving and large items | ~30 | `product` |
| **Total** | **~360–500** | |

The range is wide because it depends on how mixed the bins actually are. **This
needs a walk of the shelves before the print run** — see Open questions.

### Group labels: scan the page, tap the value

The resistor book is the case that forces this. 157 pockets at 0402 scale
cannot each carry a 20 mm QR, and shouldn't have to:

```
scan page label  →  "Book · Page 3 — 1kΩ to 10kΩ"
                 →  [1kΩ] [1.1kΩ] [1.2kΩ] [1.3kΩ] [1.5kΩ] …
                 →  tap → cart
```

One extra tap, ~8 labels instead of 157. The same pattern covers any bin
holding several closely-related parts.

## Label design

**Every label carries human-readable text under the QR. No exceptions.**

```
┌────────────────────────┐
│    ███ ▄▄ █ ▄█ ███     │
│    █ █ ██▀▄ ▀▄ █ █     │   ← 20 mm min
│    ███ ▀█▄█▀▄▀ ███     │
│                        │
│  Resistor 10kΩ 0402    │   ← human-readable, ~8 pt
│  Table Shelf · A3F9K2  │   ← location + code
└────────────────────────┘
```

Why the text matters: when a label is scuffed, solvent-stained, or the phone
won't focus, a person can still read what's in the bin and find it by search.
This single rule is what keeps the store working when the software doesn't. A
bare QR turns a damaged sticker into an unidentifiable bin.

Printing the code in text also means a member can type it in as a last resort,
which is why the alphabet excludes `0/O` and `1/l/I`.

## Printing and materials

| Choice | Recommendation | Why |
|---|---|---|
| QR size | **20 mm minimum**, larger where there's room | Reliable phone scan at arm's length |
| Error correction | **L or M** | Higher levels inflate density for no gain here |
| Printer | **Laser**, not inkjet | Inkjet smudges on contact with IPA and flux |
| Stock | **Polyester or vinyl**, not paper | These bins meet solvent, heat, and handling |
| Finish | Matte | Gloss throws glare and defeats autofocus under lab lighting |

A cheap thermal label printer (~S$100) is worth considering over A4 sheets: it
makes reprints trivial, and reprints are the recurring cost here.

## Sticking them on

~500 labels at 30–45 seconds each — clean the surface, find the right bin,
apply — is **6–8 hours**. Good work for two people and an afternoon. Do it in
location order so the batch matches the shelf you're standing at.

Clean bins with IPA first. A label applied over flux residue will lift within
weeks, and re-labelling is much slower than labelling.

## Reprints — plan for them from day one

Labels fall off, get covered by parts, and get solvent on them. From the first
release, the admin dashboard needs:

- **Print label** for any single product
- **Batch print** for a whole location (the reprint-after-a-reorganisation case)
- **Retire code** — deactivate without deleting, so old stickers fail cleanly

`stock_movements.scan_code` and `entry_method`
([data-model.md](data-model.md)) make label health measurable: a product
consistently reached by search rather than scan almost certainly has a missing
or damaged sticker. Surface that as a dashboard list rather than waiting for
someone to complain.

## Open questions

- **How mixed are the bins really?** The 360–500 range depends on whether a
  "small box" holds one part or twenty. Needs a walk of the shelves with the
  cleaned catalog in hand — do this during the
  [catalog migration](../catalog-migration.md) review pass, since that walk is
  already happening.
- Do Tier A items get a label on the *item* or on its *shelf position*? Items
  move; shelves don't. Leaning: label the item for large assets (so it's
  identifiable wherever it ends up) and the shelf for everything else.
- Is a label printer available, or do we buy one?
- Should group labels list their contents on the sticker itself (e.g. the value
  range on a book page)? Helps humans, costs label area. Leaning yes for the
  book, no elsewhere.
